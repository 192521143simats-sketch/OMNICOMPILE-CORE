## Current explicit presentation and identity override

- A normal USER has only the compiler workspace, its live metrics, current job and artifact downloads. Compute and Settings navigation/pages are removed; old /compute and /settings bookmarks redirect to /dashboard.
- Authentication/reset, admin, enrollment and worker screens remain. Backend bounded compute, settings and security/session APIs remain integrated; removing a USER page does not remove authorized worker operations.
- The user approved a complete identity rename. Package scopes, environment prefixes, worker application IDs, protocol identity and cookie/storage namespaces now use OmniCompile identifiers. This is intentionally not legacy credential compatibility: old worker enrollment/credential stores and cookies must be replaced through explicit re-enrollment/login. No automatic reuse of old worker credentials is claimed.

## Common contract and boundaries

- HTTP API uses existing /api routes; worker WebSocket envelope carries explicit protocolVersion from packages/contracts. No broad URL version migration was imposed.
- Cookie sessions are HttpOnly, SameSite=strict and Secure in production; mutations/cookie WS require an accepted Origin. Native bearer clients do not require browser Origin.
- Errors generally use {error:{code,message,details?}}. Handlers use inline Zod/service validators, not universal Fastify response schemas: this inventory does not falsely assert response-schema enforcement.
- List routes use server-side pageSchema/computePageSchema, normally 10 records. /api/networks is a compatibility discovery route bounded at 100, not the admin table pagination endpoint.
- HTTP response types are currently inferred/runtime objects; frontend api() returns any. Existing tests cover behavior but do not provide universal generated type safety.
- GET /live deliberately avoids MySQL; /ready and /health require a working query. Database interruption must affect readiness, not restart process liveness.
